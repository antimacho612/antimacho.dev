# デモを作る

デモは 3 通りある。**どれを使うかを最初に決める。**

| | 置き場所 | 目安 |
| --- | --- | --- |
| `<Sandbox>` | 記事の .mdx に直接 | 20 行程度まで。記事を読みながらコードも読めるのが利点 |
| `<Demo id="...">` | `src/demos/<id>/` | それより大きいもの、特に JS を伴うもの。補完と整形が効く |
| `<Compare>` | 記事の .mdx に直接 | 「これを付けるとこう変わる」を 2 つ並べて見せるとき |

書き方の詳細は [src/demos/README.md](../../../src/demos/README.md) にある。
props の一覧は `src/content/posts/General/mdx-components.mdx` に実物付きでまとまっている。

## 1. 何を確かめさせたいのかを 1 文にする

「コンテナの幅を変えるとレイアウトが切り替わること」のように、**動かした結果として
何が見えるか**を先に言葉にする。これが `title`（キャプション）になり、デモの構成も決まる。

ここが曖昧なままだと、ただ動くだけで何も分からないデモになる。曖昧ならユーザーに聞く。

## 2. 重複を調べる

`src/demos/*/demo.json` と各 `index.html` を Glob で列挙し、同じ内容が既にないか見る。
既存デモに手を入れれば済むなら、新規に作らずそちらを直す。

## 3. 作る

**`<Demo>` の場合** — [_template/](../../../src/demos/_template/) を `src/demos/<id>/` にコピーして書き換える。
id はディレクトリ名と揃える（kebab-case）。ファイルを置くだけで参照でき、index への登録は不要。

**`<Sandbox>` / `<Compare>` の場合** — 記事の .mdx にテンプレートリテラルで直接書く。

### 実行環境の制約

デモは iframe の `srcdoc` に隔離される（`sandbox="allow-scripts allow-forms"`、
`allow-same-origin` なし）。つまり:

- 親ページの DOM・localStorage・テーマトークン（`var(--primary-color)` など）には**触れない**
- 色は値を直接書く。アクセントは記事側と揃えて `#8b5cf6` / `#a78bfa` 系
- 注入される CSS は `body { margin: 0; padding: 16px }` 程度だけ。
  **`box-sizing` は既定の `content-box` のまま**なので、必要ならデモ側で指定する
- テーマ切り替え時は `<html>` に `dark` クラスが付く。配色を変えたいなら `html.dark` を見る

### よくある失敗

- `width: 100%` に `box-sizing: border-box` を付け忘れて横に溢れる（スクロールバーが出る）
- 固定幅で作ってしまい、狭い画面や広い画面で破綻する
- コントロール（スライダー等）を付けたのに、初期表示で何も起きず意図が伝わらない
  → 初期状態から違いが見えるようにするか、キャプションで操作を促す

## 4. 検証する

```bash
npm run check
npm run build
```

そのうえで **`npm run dev` で実際に開いて目視確認する**。iframe の中は隔離されていて
外から DOM を読めないので、ここは省略できない。見るのは次の 4 点。

1. 意図した動きになっているか
2. iframe に不要なスクロールバーが出ていないか
3. 幅を変えても破綻しないか
4. ダークモードで見えなくなる要素がないか

## 5. 報告する

- 作ったデモの種類（Sandbox / Demo / Compare）とファイルパス
- そのデモで何が確かめられるか
- check / build の結果と、目視で確認したこと
